Plooy — VPS operations (canonical)
==================================

## Paths (single source of truth)

  Install dir:  /opt/sineoda
  Database:     /opt/sineoda/persistent/data/sineoda.db
  Uploads:      /opt/sineoda/persistent/uploads/
  API port:     3001 (nginx → 80/443)

## Normal deploy

  PC:   npm run check:deploy && git push origin main
  VPS:  cd /opt/sineoda && git pull && bash deploy/rebuild-vps.sh

## Emergency (502 / black screen)

  cd /opt/sineoda && bash deploy/recover-vps.sh

  Fresh install (folder missing):
  curl -fsSL https://raw.githubusercontent.com/sanalfikret/sineoda/main/deploy/vps-rescue.sh | bash

## Health check

  curl -s http://127.0.0.1:3001/api/health
  → ok: true, storage.dbExists: true, auth.jwtExpiresIn: "30d"

  Browser: hard refresh Ctrl+Shift+R — test / and /en

## Script map

| Script | When |
|--------|------|
| deploy/rebuild-vps.sh | Code update on VPS (canonical) |
| deploy/recover-vps.sh | git pull + rebuild |
| deploy/vps-rescue.sh | First install or lost folder |
| deploy/backup-vps.sh | Auto before rebuild |
| deploy/restore-db.sh | Manual DB restore only |
| deploy/sync-to-vps.ps1 | Deploy from PC without GitHub |

Deprecated wrappers (call recover/rebuild): vps-now.sh, update-vps.sh, deploy-vps.sh

## Disk cleanup (safe — never touches persistent/)

  cd /opt/sineoda && bash deploy/cleanup-vps.sh            # report only
  cd /opt/sineoda && bash deploy/cleanup-vps.sh --apply    # remove old docker images/cache, broken copies, logs
  add --deep to also drop the newest broken copy and host node_modules

  Growth sources: old docker images per rebuild, builder cache,
  /opt/sineoda-broken-* copies from archive recovery, container json logs
  (now capped 10 MB x 3 in docker-compose.yml), journald.

## Never

  docker compose down -v
  rm -rf persistent/
